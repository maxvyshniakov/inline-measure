# Inline Measure measurement work — 2026-11-05

The package keeps full-substring shaping and its existing `linebreak` dependency.
It now avoids redundant Canvas state writes, reuses numeric candidate widths
inside multiline feasibility passes, and proves the native minimum in exact
mode even when Canvas overestimates it. No Pretext code or runtime dependency
was added.

The [pinned Pretext 1.0.0 research](pretext-1.0.0-research.md) explains the
replacement decision and the preparation, cache and Canvas-state approaches
considered here. Its upstream benchmark claims are separate from our measured
results below.

## Accuracy and regression checks

- 63 native-DOM fixtures pass in each engine. Baseline had 5 failures in
  Chromium/Firefox and 7 in WebKit: native breaks could fit a date in three
  lines more narrowly than the model, the exact upper bound omitted word
  spacing, and WebKit also exposed overestimated long-token widths.
- Reusable string measurers preserve shorthand small-caps/stretch across
  interleaved computed-style calls. Numeric variants no longer enter an invalid
  Canvas font shorthand when the computed shorthand is empty.
- Delayed network font loading refreshes Canvas and tabular glyph calibration
  in all engines: [raw font probe](font-loading.json). Firefox/WebKit dispatched
  `loading` but no `loadingdone`; the implementation also waits for the loading
  cycle's `fonts.ready`.
- 65 unit/report tests pass. Focused RED/GREEN evidence included repeated Canvas
  writes 18 versus 9; invalid numeric shorthand measuring 20 versus 28; exact
  overestimate 10 versus 5; missing word-spacing upper bound 4 versus 7;
  stale font 10 versus 18; shorthand caps/stretch 16 versus 14.4; repeated
  candidate slices 14 versus a bound of 7; and nearby native reads 6 versus 4.
- Types, lint (including harness scripts), changelog checks, build and packed
  consumer pass. The archive has 19 files, all three entrypoints import from
  plain Node, and declarations check under NodeNext without `skipLibCheck`.

## Measured review iteration

The first accurate minimum-width implementation made WebKit exact three-line
work +53.9% slower than the baseline. A three-node batched-neighbor prototype
showed no supported gain and was rejected. A second adjacent-width proof before
full downward binary search reduced that implementation from 44.10 to 35.66 ms
in the scratch experiment, with every answer unchanged. It reduced rectangle
reads from 923 to 651 and scroll-width reads from 606 to 369 per 200-row batch.
That bounded nearby proof was adopted; the final current-source recapture is
36.10 ms. Earlier raw captures remain as `after-before-nearby-*.json`,
`neighbor-prototype-webkit.json` and `nearby-prototype-webkit.json`.

## Commands

```sh
bun run perf:test
bun run verify:browser --browser chromium
bun run verify:browser --browser firefox
bun run verify:browser --browser webkit
bun run verify:fonts
bun run perf --ref HEAD --browser chromium --samples 7 --iterations 50 --output artifacts/perf/before.json
bun run perf --browser chromium --samples 7 --iterations 50 --baseline artifacts/perf/before.json --strict --output artifacts/perf/after.json
bun run perf:report artifacts/perf/before.json artifacts/perf/after.json --strict
```

The heavy commands own their leases; all timing captures ran with every machine
slot, and correctness/build tests used one slot. No commits, pushes, releases or
publishing were performed. These synthetic measurements are independent of
Data Grid; they are not claims about Data Grid resize performance or installed
Safari acceptance.
