# Pretext 1.0.0 vs Inline Measure — 2026-11-05

Do not replace Inline Measure wholesale. Pretext 1.0.0 substantially improves wrapping accuracy and its own repeated-layout performance, but still explicitly does not support the separate CSS settings for tabular numbers, OpenType features and variable-font axes that Inline Measure's DOM paths accommodate. The strongest transferable idea is to prepare and measure once, then evaluate candidate widths using numeric data; the next is bounded reusable measurement caches and avoiding redundant Canvas state writes. These are recommendations inferred from code inspection, not measured speedups for Inline Measure.

## What changed in Pretext

1. Browser-specific break engines replace handcrafted rules. It ports Blink/WebKit pair tables and ICU rules, and Gecko's breaker, with generated browser data; grapheme segmentation also uses browser rule data instead of Intl.Segmenter except dictionary languages. This is meaningful accuracy work for punctuation, URLs, CJK and soft hyphens. It is still a port of selected browser versions, not executing the active browser's live breaker. Ports have deliberate differences, e.g. dictionary runs use Intl.Segmenter and no element-level lang is read. [Changes](https://github.com/chenglou/pretext/blob/4a98f37b1e5396a73197f17c13f3128c15d8c17c/CHANGELOG.md#changed), [port scope and differences](https://github.com/chenglou/pretext/blob/4a98f37b1e5396a73197f17c13f3128c15d8c17c/src/line-breaks.ts#L1-L35).
2. Rich inline is analyzed as one paragraph instead of independently prepared spans, so span boundaries no longer invent breaks and punctuation and words split across spans stay together. Useful for future styled text; Inline Measure currently measures plain strings, so this is not a current need. [Changelog](https://github.com/chenglou/pretext/blob/4a98f37b1e5396a73197f17c13f3128c15d8c17c/CHANGELOG.md#changed).
3. Author's benchmark claims against 0.0.9: layout at new width 3–6x faster; repeated prepare 1.1–13x, depending language; cold text 1.5–2.1x for English/CJK. Tested Chrome154/Firefox157/Safari27 on M5 Max. They also report cold-load cost +0.4/+1.1/+0.7ms and first-prepare regressions for some UI labels. These are NOT measurements against Inline Measure or on this machine. Bundle grows approximately 16→40 KB gzip, rich entry 16→44KB, principally browser tables. [Exact benchmark context and costs](https://github.com/chenglou/pretext/blob/4a98f37b1e5396a73197f17c13f3128c15d8c17c/CHANGELOG.md#changed).

## Constraints still present

The pinned README explicitly excludes `font-variant-numeric`, `font-optical-sizing`, `font-feature-settings` and `font-variation-settings`; variable settings apply only via Canvas font shorthand where possible. It assumes default font kerning and word spacing. It warns system-ui/-apple-system are unsafe for macOS layout accuracy, and generic fonts/language/font loading can change results. It requires `overflow-wrap: break-word`, whereas Inline Measure's exact multiline probe sets `overflowWrap: normal`. Pretext answers line count/height at width; Inline Measure's multiline contract answers minimum width for N lines. An adapter would still need an inverse search and must preserve unbreakable-word semantics. [Caveats](https://github.com/chenglou/pretext/blob/4a98f37b1e5396a73197f17c13f3128c15d8c17c/README.md#caveats).

Inline Measure's `auto` single-line path calibrates glyphs for tabular numeric styles against DOM and `exact` copies feature/variation settings onto DOM probes. Its multiline path uses Canvas for candidate widths even under auto, with DOM verification only for exact; do not overstate every current Inline Measure path as fully feature-aware. Local: `src/index.ts:206-281`, `src/multiline.ts:256-288`.

## Approaches worth borrowing, in priority order

1. **Prepared multiline geometry.** Pretext `layout()` does no Canvas calls, DOM reads, strings or per-line allocation: it counts using premeasured widths, flags and optional edge corrections, with a specialized simple loop for ordinary text. Inline Measure currently slices candidate substrings inside each feasibility scan and measures/cache-looks them up, and rescans every break opportunity for every line and every binary-search width (`src/multiline.ts:180-243`). Separate preparation from feasibility so the inverse search and repeated resizes reuse numeric data. Preserve shaping correctness: blindly summing isolated glyph/word widths loses kerning and joined-script behavior, so validate against exact DOM and retain a fallback. [layout](https://github.com/chenglou/pretext/blob/4a98f37b1e5396a73197f17c13f3128c15d8c17c/src/layout.ts#L158-L167), [simple counter](https://github.com/chenglou/pretext/blob/4a98f37b1e5396a73197f17c13f3128c15d8c17c/src/line-break.ts#L305-L370).
2. **Bound caches and reuse them across calls.** Pretext caches per font and text segment, including metrics/following-space fits. It bounds total segments at 262144, clearing only between preparations so in-progress state stays coherent. Inline Measure candidate cache is per invocation; tabular glyph cache is global and currently unbounded. Borrow the principle and tune smaller bounds to our label workloads, not their chat-specific threshold. Keys/invalidation must cover our full style signature, fonts, language and possibly device pixel ratio. [cache shape](https://github.com/chenglou/pretext/blob/4a98f37b1e5396a73197f17c13f3128c15d8c17c/src/measurement.ts#L364-L454), [font/language/zoom caveats](https://github.com/chenglou/pretext/blob/4a98f37b1e5396a73197f17c13f3128c15d8c17c/README.md#caveats).
3. **Avoid redundant Canvas state writes.** Inline Measure resets then reassigns text properties and gets the 2D context on every measurement (`src/index.ts:81-120`). Pretext keeps context state and assigns font/letter spacing only when changed; cache hits do not touch Canvas. A smaller, local optimization with lower architectural cost; preserve isolation for interleaved measurers. [getContext](https://github.com/chenglou/pretext/blob/4a98f37b1e5396a73197f17c13f3128c15d8c17c/src/measurement.ts#L1394-L1405).
4. **Bound expensive prefix work.** For emergency word wrapping Pretext measures prefixes at most 96 graphemes, then falls back to pair-context to avoid quadratic prepare work on giant tokens. Relevant if we add reusable per-token shaping or emergency wrapping; do not add break-word behavior accidentally. [bounded prefix policy](https://github.com/chenglou/pretext/blob/4a98f37b1e5396a73197f17c13f3128c15d8c17c/src/measurement.ts#L425-L432).
5. **Borrow test fixtures and engine research selectively.** Cases for signed letter spacing, browser-specific soft-hyphen glyph U+2010 (Inter differs from ASCII hyphen), CJK punctuation, emojis and loaded font invalidation are more valuable immediately than importing 23KB of browser data. Our current multiline code appends ASCII '-' for SHY. Browser tables are justified only if our real fixtures expose a meaningful linebreak-package gap. [fixes](https://github.com/chenglou/pretext/blob/4a98f37b1e5396a73197f17c13f3128c15d8c17c/CHANGELOG.md#fixed).

## Recommendation and unknowns

Prototype prepared multiline feasibility plus Canvas-state reuse first; compare against current code and Pretext under identical CSS/semantics. Include Inter regular/tabular, currency/percent/date labels, multilingual strings, soft hyphens, negative letter spacing and long tokens. Measure cold preparation, warm repeated calls, new-width checks, Canvas/DOM call counts, allocation and bundle cost separately. Use DOM as accuracy oracle in Chromium, Firefox and WebKit. No benchmark was run in this research task; speed benefit remains an inference pending that experiment.

Do not wholesale copy browser ports without carrying their third-party notices: Pretext's LICENSE includes its MIT license plus Chromium/WebKit/ICU/ICU4X notices. [Pinned LICENSE](https://github.com/chenglou/pretext/blob/4a98f37b1e5396a73197f17c13f3128c15d8c17c/LICENSE).
